# 03 · 首页（三态日历）

> 首页是 **整屏三态 morph** 模型：`month`（月）→ `week`（周）→ `year`（年）。
> 全部几何取自 iOS `Views/Home/{CalendarLayout,CalendarPaneViews,HomeView}.swift`，单位换成 dp；
> 顶栏与底栏换成 Material 3。
>
> 证据：`docs/ios-reference/v3-home.md`（含 `file:line`）· 设计稿 [`mockups/png/02-home.png`](mockups/png)
> 代码：`ui/home/{HomeScreen,HomeViewModel,CalendarLayout,CalendarGrid,CalendarCanvas}.kt`

---

## 1. 状态机

```
                    ┌──────────────────────────────────────┐
                    │  month  （初始态，冷启动恒为此态）      │
                    └──────────────────────────────────────┘
                       │ 点任意日期              ▲ 点左胶囊（‹ 九月）
                       │（expand 0→1，滑动）      │（expand 1→0，滑动）
                       ▼                        │
                    ┌──────────────────────────────────────┐
                    │  week   （星期栏 + 周条 + 当日内容）    │
                    └──────────────────────────────────────┘

                    ┌──────────────────────────────────────┐
   点左胶囊 ‹2026年  │  year   （3 × 4 迷你月历）             │
   （zoom 0→1，缩放）└──────────────────────────────────────┘
        month ─────────────────────────────► year
              ◄─────────────────────────────
                点任意迷你月（zoom 1→0，缩放）
```

| 迁移 | 触发 | 动画 | 进度量 |
| --- | --- | --- | --- |
| 月 → 周 | **点任意日期** | 滑动 | `expand: 0 → 1` |
| 周 → 月 | 点顶栏左胶囊（`‹ 九月`） | 滑动 | `expand: 1 → 0` |
| 月 → 年 | 点顶栏左胶囊（`‹ 2026年`） | 缩放 | `zoom: 0 → 1` |
| 年 → 月 | 点任意迷你月 | 缩放 | `zoom: 1 → 0` |
| 任意 → 今年当月 | 点顶栏右胶囊（`今天`） | 年态：先 morph 回当月；月/周态：滚动到今天 | — |

> **平板横屏（分栏）例外**：分栏下只有月态。切进分栏时无动画收回月态，
> 年份入口随顶栏一起消失（对齐 iOS，见 §2.3、§3.4、§10 第 5 条）。

**必须遵守的三条状态规则**（iOS 踩过的坑）：

1. **可见性由 `mode` 决定，不由动画值决定。**
   年层"在不在"必须只从 `mode` 推出；`zoom` / `expand` 只负责过渡。
   违反这条的后果：配置变更（旋转 / 切深色）后动画值回到 0，年历整屏消失，只剩顶栏（v2 的 D2 缺陷）。
   **恢复时把进度量 `snapTo` 到终值**，不要让它停在 0。
2. **morph 进行中禁止输入。** `morphing = (正在 morph)` 期间：三层不重建、分页器 `disabled`、
   返回 / 点日期 / 今天三者全部 guard 掉。
3. **状态不持久化。** 冷启动恒为「今天 + 月态」。收到 `日记数据变更` / `UI 设置变更`
   （语言、主题、周起始、`auto_time`、导入备份）时重置回「今天 + 月态」。

### 1.1 显示态与"上次停留"无关

不要记住"用户上次在年态" —— 每次回到首页都是月态。理由：首页的核心动作是"看今天 / 点某天写日记"，
停在年态会让这个动作多两步。

## 2. 几何

### 2.1 竖屏（手机 · 平板竖屏同构）

```
┌──────────────────────────────────┐
│ statusbar                         │ 32
├──────────────────────────────────┤
│ ← 12dp 上边距                      │
│ [ ‹ 2026年 ]            [ 今天 ]  │ 52   ← 胶囊行，合计 64
│                                   │
│  九月                             │ 72   ← 大标题槽 BIG_TITLE_H
│  一 二 三 四 五 六 日              │ 30   ← 星期栏 WEEKDAY_H
│ ─────────────────────────────────│
│   1   2   3   4   5   6           │
│  二十 廿一 廿二 廿三 廿四 廿五       │ cellH = (区高 − 102) / 6
│  ...                              │ ← 恒除 6；5 行的月份下方留白
├──────────────────────────────────┤
│  日记   足迹   搜索   设置         │ 80   ← NavigationBar
├──────────────────────────────────┤
│              ▬                   │ 24   ← 手势条
└──────────────────────────────────┘
```

| 常量 | 值 | 说明 |
| --- | --- | --- |
| `TOPBAR_H` | **64** | 12dp 上边距 + 52dp 胶囊行。M3 small top app bar 的高度是 64，与 iOS 的 12+52 巧合一致 |
| `BIG_TITLE_H` | **72** | 大标题（`九月`）的槽位。**它同时是 morph 的终点**，不能改 |
| `WEEKDAY_H` | **30** | 星期栏 |
| `WEEK_STRIP_H` | **68** | 周态里那一行日期 |
| `DAY_TITLE_H` | **40** | 周态日期标题行（`9月26日 周六 丙午年八月十六`） |
| `YEAR_TITLE_H` | **62** | 年历的 `2026年` 标题块 |
| `YEAR_PAD` / `YEAR_SPACING` | **16 / 6** | 年历页边距 / 卡片间距 |
| `MINI_PAD` / `MINI_TITLE_H` | **6 / 17** | 迷你月卡片内缩 / 月份标题高 |

**日历区高度** = `可用高 − 64`，下限 320dp。
**格高** `cellH = (日历区高 − 72 − 30) / 6`。

> ### 为什么"恒除 6"？
> 因为 **5 行的月份（如 2026-09）要在下方留出一行的空白**。
> 若改成 `除以实际行数`，翻月时格子高度会在两个值之间来回跳，整块日历上下抖动。
> 留白好过抖动 —— 这条与 iOS 一致，**不要"优化"**。

**日号与农历字号**（跟着格高走，不写死）：

```kotlin
fun dayFont(cellH: Float)   = min(20f, max(13f, cellH * 0.34f))
fun lunarFont(cellH: Float) = min(11f, max(9f,  cellH * 0.18f))
```

> 写死 20 / 11 的后果：分栏或横屏把格子压到 40dp 时，日号和农历重叠。

### 2.2 平板（Medium · 800 × 1280 竖屏）

- 侧栏 96dp；剩余 704dp 内**日历限宽 640dp 居中**（`min(640, 内容宽)`）。
- 其余几何与手机**完全相同**（大标题 72、星期栏 30、恒除 6）。
- 三态 morph 与手机一致。

### 2.3 平板（Expanded · 1280 × 800 横屏，分栏）

```
┌────────┬───────────────────────────┬──────────────────────────────┐
│        │  九月  2026年              │ 34  ← 紧凑标题行              │
│  rail  │  一 二 三 四 五 六 日       │ 26  ← 紧凑星期栏              │
│  96dp  │  ─────────────────────    │                              │
│        │   1   2   3   4   5   6    │     9月26日 周六  丙午年…  [今天] │ 44
│        │   …                        │ ──────────────────────────── │
│        │   28  29  30               │  ┌────────────────────────┐  │
│        │                            │  │ 21:40                  │  │
│        │  ↕ 上下滑翻月               │  │ 字体样式自检            │  │
│        │                            │  └────────────────────────┘  │
└────────┴───────────────────────────┴──────────────────────────────┘
   ← masterWidth 260–440dp →          ← detailWidth ≥ 240dp →
```

| 常量 | 值 | 说明 |
| --- | --- | --- |
| `COMPACT_TITLE_H` | **34** | 分栏左栏的标题行（大标题 24sp） |
| `COMPACT_WEEKDAY_H` | **26** | 分栏左栏的星期栏 |
| 分栏间距 | **16.5dp** | 16dp 页边距 ×2 + 0.5dp 分隔线（实占） |
| 右栏标题行 | **44** | 比竖屏的 40 高 4dp，为了放得下「今天」胶囊 |
| 右栏正文列宽 | **max 560dp** | 分栏里再限一次宽，否则一行 100+ 字 |

**分栏下没有顶栏，也没有年态与周态**：切进分栏时无动画收回月态（对齐 iOS）。
左栏只有「上下滑翻月」与「点日期」两种交互；`今天` 在右栏标题行。

**密度降级**：左栏可用高不足时，月历自动降级为**周条**（只画选中日所在那一行）。
判据见 §5.3。

## 3. 顶栏胶囊行

两枚 M3 **assist chip**（40dp 高、full 圆角）：

| 位置 | 变体 | 标签 | 点击结果 |
| --- | --- | --- | --- |
| 左 | `outlined`（1dp `outlineVariant` 描边，`onSurface` 文字）+ 前导 `chevron_left` 20dp | 月态：`2026年`；周态：`九月`；**年态：整枚隐藏** | 月态 → 年态；周态 → 月态；年态 → 不可点 |
| 右 | `elevated`（`surfaceContainerLow` + `shadow-1`）+ 前导 `calendar_today` 18dp | 相对日文案（见下） | 回到今天（年态时先 morph 回当月） |

### 3.1 为什么是 chip 而不是按钮

iOS 用两枚玻璃胶囊。Material 里最接近"轻量、可点、带前导图标"的组件就是 **assist chip**：
左侧那枚是导航（outlined，中性），右侧那枚是动作（elevated，微微浮起，读作"可点的动作"）。
**不要**用 `FilledTonalButton`（太重，会把首页主色抢走），也不要用 `TextButton`（没有容器，在日历上方会飘）。

### 3.2 年态为什么隐藏左胶囊

iOS 在年态把左胶囊 `opacity 0` 且 `allowsHitTesting(false)`。Android **照做**，但**必须**同时提供另外两条退路：

- **系统返回键**：年态 → 月态（`PredictiveBackHandler`，见 `02-adaptive-and-navigation.md` §6）；
- **点任意迷你月** → morph 回该月。

> 不能只留"点迷你月"一条路（iOS 那样），因为 Android 用户在满屏无返回按钮时第一反应是系统返回键。

### 3.3 右胶囊的文案（**Android 的一处改进**）

```
if (选中日 属于 当前显示的月)  label = 相对日(选中日)      // 今天 / 昨天 / 明天 / 3 天前 …
else                          label = 具体日期(选中日)     // 9月26日
```

**为什么**：iOS 竖屏翻月**不改选中日**（§6.2）。于是可能出现"屏幕上是 12 月、胶囊却写着『今天』"的误导。
Android 保留"翻月不改选中日"这个行为（它保证翻月纯粹是浏览，不会意外改变目标日期），
但让胶囊在两者脱节时说实话。

相对日文案表（与 iOS `L10n.relativeDayLabel` 对齐）：

| 差值 | 文案 |
| --- | --- |
| 0 | 今天 |
| −1 / +1 | 昨天 / 明天 |
| −2 … −6 / +2 … +6 | N 天前 / N 天后 |
| 其它 | 具体日期（`9月26日`） |

### 3.4 分栏时整条胶囊行隐藏

平板横屏分栏时**没有这一行**：整条隐藏。`今天` 收进右栏标题行，**严格一处**，
不允许两处同时出现（v2 的 D9 就是这个重复）。**年份入口也随之消失** —— 分栏下年态不可达（§2.3、§10）。

## 4. 月态

### 4.1 一格画什么

```
        ┌─────────────┐
        │     26      │  ← 日号：dayFont，tabular-nums
        │    十六      │  ← 农历：lunarFont，onSurfaceVariant（仅中文 + 有空间时）
        │    ▬▬        │  ← "有日记"标记：min(20, cellW×0.5) × 2dp 圆角横线，主色
        └─────────────┘
          ↑ 选中/今天：圆
```

### 4.2 四个状态的**完整**表达（颜色 + 非颜色）

| 状态 | 非颜色表达 | 颜色 | 优先级 |
| --- | --- | --- | --- |
| **今天** | **1.5dp 主色圆环**（不是实心） | 圆环 `primary`；日号与农历 `primary` | 2 |
| **选中** | **主色实心圆** | 底 `primary`；日号与农历 `onPrimary` | 1（最高） |
| **有日记** | 日号下方 **2dp 主色短横线**，宽 `min(20, cellW × 0.5)` | `primary` | 3 |
| **未来日期** | 日号与农历一律 `onSurfaceVariant`（**不用 alpha**：0.35 的对比度只有 2.19:1，违反 WCAG AA） | `onSurfaceVariant` | 4 |

- 圆直径 `circleD = min(cellW − 3, 内容高 + 14, cellH − 3)`。
- **今天与有日记可以共存**（裁决 #8）：今天画圆环，同时画短横线。
  但**选中时不再画短横线**（实心圆上的横线看不清）。
- **未来日期用语义色 `onSurfaceVariant`**（iOS 是整格 `alpha × 0.35`，那样对比度只有 2.19:1，R3 实测后已改）。
  我们也不画周末列的配色，所以"和周末混淆"的顾虑不存在。
- **相邻月的日期一律不画**（`showAdjacent = false`）：格子留空、不可点、不进无障碍树。
  画相邻月日期会让"这个月"的边界消失（v2 的 D4）。

### 4.3 行与分隔线

- 每行顶部 1dp `outlineVariant` 分隔线，**第一行不画**。
- **整行都不属于当月时不画分隔线**（v2 的 D12）。
- 网格**顶格对齐**紧贴星期栏，剩余高度形成底部留白（§2.1）。

### 4.4 星期栏

- 文案来自 `AppSettings.week_start`（`周一` / `周日`），纯文本，13sp，`onSurfaceVariant`。
- **周末列不做特殊配色**（iOS 也没有）。首轮给周末列加了 `onSurfaceVariant @60%`，对比度只有 3.16:1，已回退。

## 5. 周态与年态

### 5.1 周态（竖屏 / 平板竖屏）

```
星期栏（30）
周条（68）           ← 只有选中日所在的那一周，7 格
──────────────────
日期标题行（40）      `9月26日 周六`    `丙午年八月十六`      [今天]
──────────────────
当日内容（剩余高度，可滚动）
```

- 周条格：日号 20sp + 农历 11sp；选中 = 实心圆；有日记 = 短横线；**不画分隔线**。
- 当日内容（`DayContentView`）：
  - 有片段 → 每段一张卡片（时间 `schedule` 14dp + 地点 `place` 14dp + 富文本）；
    若选中日是**今天**，末尾追加一枚 filled 按钮「继续写今天的日记」。
  - 没有片段 → 空态：`edit` 图标 28dp（未来日换 `dark_mode`）+ 文案 + （仅当非未来日且是今天）「写日记」按钮。
  - 内容左右内边距 20dp，顶部 18dp，底部 96dp（让最后一张卡能滚出底栏）。
- **左右滑翻周**：翻的是"选中日所在周"，位移量 = 两周相差的天数，选中日跟着走。

### 5.2 年态（竖屏 / 平板竖屏）

```
2026年                        62   ← 大标题
┌────────┬────────┬────────┐
│ 1月     │ 2月     │ 3月     │
│ 一二三四五六日 …        │      cardH = (区高 − 62 − 8 − 18) / 4
├────────┼────────┼────────┤
│ 4月     │ 5月     │ 6月     │
…
```

| 项 | 值 |
| --- | --- |
| 列数 × 行数 | **3 × 4** |
| 日历/年历最大宽度 | **640dp**（竖屏与平板竖屏；分栏时改走 `masterWidth`） |
| 卡片宽 | `(宽 − YEAR_PAD×2 − YEAR_SPACING×2) / 3` |
| 卡片高 | `(区高 − YEAR_TITLE_H − 8 − YEAR_SPACING×3) / 4` |
| 卡内 | `MINI_PAD 6` 内缩；月份标题 `MINI_TITLE_H 17`；下方 6 行 × 7 列迷你格 |
| 迷你日号字号 | `min(14, max(9, min(cellW × 0.95, cellH × 0.5)))` |
| **迷你月里不画农历** | iOS `miniLunarHidden = 0` |
| 迷你月里不画分隔线 | 同 |

迷你格状态：**有日记** = 日号加粗 + `primary`；**今天** = 实心圆（`primary` 底 + `onPrimary` 字）；
**选中日所在的那个月**的卡片给一层轻微高亮（`surfaceContainerHigh` 底）—— 这是 Android 加的，用来回答"我现在在哪个月"。

- **上下滑翻年**（不是左右）。
- 点卡片 → 缩放 morph 回该月。
- 卡片整块可点，涟漪**有界**（用 `Modifier.clip(shape)` + 默认 indication，不要 `indication = null`）。

### 5.3 密度降级（只在空间真的不够时触发）

```
perRow = floor(可用高 / 行数)          // 行数 = displayedWeeks().count（去掉末尾整周非本月的填充行）
perRow >= 60  → 显示农历
perRow >= 38  → 不显示农历
否则          → 降级为「周条」（只画选中日所在行）
```

- **行数必须传"实际要画的行数"**，不能传固定的 6。否则"5 行放得下"会被误判成"6 行放不下"，
  平板横屏于是错误地降级成周条（iOS 踩过这个坑）。
- 降级时 `cellH` 被夹回 `WEEK_STRIP_H`，否则会出现一行 200dp 高的巨大日期。

## 6. 手势

| 手势 | 位置 | 结果 |
| --- | --- | --- |
| **上下滑** | 月态月格区域 | 翻月（上一月 / 下一月）。**翻月不改选中日** |
| **上下滑** | 年态 | 翻年 |
| **左右滑** | 周态周条区域 | 翻周。**选中日跟着位移**（保持"周几"不变） |
| **上下滑** | 平板横屏左栏 | 翻月。**把选中日带到新月份的同一天**（夹到该月最后一天） |
| **点日期** | 月态 | 竖屏/平板竖屏 → morph 进周态；**平板横屏 → 只换选中日** |
| **点日期** | 周态 | 换选中日，不 morph |
| **点左胶囊** | 月态 / 周态 | 年态 / 月态 |
| **点右胶囊** | 任意 | 回今天 |
| **点迷你月** | 年态 | morph 回该月 |
| **长按** | 任意 | **无**（iOS 也没有） |
| **捏合** | 任意 | **无**（见 `README.md` 有意分歧） |

### 6.1 跟手与回弹

翻页跟手，松手后按阈值决定去留：

```
翻下一页：predictedEnd < −90dp  或  (位移 < 0 且 |位移| > 60dp)
回弹：    rubber(x) = c · x / (x + c)，c = pageSize × 0.25
```

### 6.2 翻月为什么不动选中日（竖屏）

竖屏月态里**选中日不可见**（除非它正好落在当前月）。所以"翻月"是一次纯浏览动作，
不该悄悄改变"我要写哪一天"的目标。选中日在点日期时才改变。

> 唯一的副作用是顶栏胶囊可能显示与当前月无关的日期 —— 已由 §3.3 的文案规则解决。

平板横屏**相反**：右栏常驻显示选中日的内容，翻月若不动选中日，右栏就会显示"另一个月的某天"，
与左栏脱节。所以横屏翻月要把选中日带到新月份的同一天。

### 6.3 未来日期

点未来日期**不打开编辑器**，只给一条 Snackbar：`这一天还没到，不能写日记`（带「知道了」动作）。
未来日的空态用 `dark_mode` 图标 + 「这一天还没到」，且**不提供**写入按钮。

## 7. morph 几何

> **逐帧分解图见 [`mockups/png/08-flows.png`](mockups/png) 第 2、3 节** —— 实现时直接对着比对。

morph 的每一个端点**必须取自真实排版用的同一个矩形、同一组常量**。任何"再算一遍"都会在收尾时跳一下。

### 7.1 月 ↔ 周（滑动，`expand: 0 → 1`）

| 图层 | 起点（月态） | 终点（周态） |
| --- | --- | --- |
| 大标题槽 | 高 72，标题 32sp | 高 0，`alpha → 0` |
| 星期栏 | y = 72，高 30 | y = 0，高 30 |
| **选中日那一行** | 它在月网格里的 y 与 `cellH` | y = 30，高 68 |
| 其它行 | 各自 y 与 `cellH` | `cellH → 0`，`alpha → 0` |
| 农历行 | `alpha = 1` | `alpha` 插值 |
| 分隔线 | `alpha = 1` | `alpha → 0` |
| 当日内容块 | `alpha = 0` | `alpha = 1`，从下方 24dp 处上移到位 |

### 7.2 月 ↔ 年（缩放，`zoom: 0 → 1`）

| 图层 | 起点 | 终点 |
| --- | --- | --- |
| **锚点** | 源月卡片中心（年态里的 `yearCardRect(month)` 中心） | 同左 |
| 年历层 | `scale = 1.6`，`alpha = 0` | `scale = 1`，`alpha = 1` |
| 月标题 | 大标题槽位置（72 高，32sp） | 该月卡片的标题矩形（`miniTitleRect`，17 高，13sp） |
| 月网格 | 整月网格矩形 | 该月卡片的网格矩形（`miniGridRect`） |
| 日号字号 | `dayFont(cellH)` | `miniDayFont(cellW, cellH)` |
| 农历 | `alpha = 1` | `alpha = 0` |

> **标题矩形必须两处共用一个函数**（`miniTitleRect` / `miniTitleInCard` + `miniGridInCard`）。
> 两侧各写一套时，`.position` 与取整会差 1/3dp，morph 收尾换回真实年历时月份数字会"啪"地挪一下。

### 7.3 动画参数

| 项 | 值 |
| --- | --- |
| 时长 | **400ms** |
| 缓动 | `easing.emphasized` = `CubicBezierEasing(0.2f, 0f, 0f, 1f)` |
| 月↔年 与 月↔周 | **共用同一条曲线**（iOS 的 `morphAnimation == morphSlideAnimation`） |
| 减弱动态效果 | 180ms `easing.linear`，**只做交叉淡入，不做位移** |
| 触觉 | morph 开始时不给；点日期/点胶囊时各给一次 `TextHandleMove` |

> 为什么不用 `easeInOut`：它从零速度起步，前 1/4 时间只走完约 13% 进度，观感上"开头一段几乎不动"，
> 比月↔周切换慢半拍。M3 的 `emphasized` 起步带速度、尾部减速，两条 morph 节奏一致。

## 8. 无障碍

| 元素 | 语义 |
| --- | --- |
| 月格（每天） | `contentDescription` = 「9月8日 周二，农历廿七，有日记，未选中」；`Role.Button`；**整格是一个可点元素** |
| 月格的无障碍动作 | 提供 `CustomAccessibilityAction`「查看这一天的日记」；**不要**声明 `ScrollAxisRange` 之类的 adjustable 却没有回调（iOS 的 `adjustable` 动作因未传回调而失效） |
| 星期栏 | 纯装饰，`clearAndSetSemantics {}` |
| 周条 | 与月格同样的语义（iOS 的周条完全没有 a11y，Android 要补） |
| 年历迷你格 | 整卡一个元素：「2026年9月，有 5 天记录了日记，点击查看」 |
| 顶栏胶囊 | 「返回年历」/「回到今天」（`今天` 胶囊在 iOS 上没有 identifier，Android 要有稳定的语义） |
| 分页器 | `beyondViewportPageCount = 0`，避免同名元素出现 2–3 份 |
| 动态字体 | 日号与农历按**半速**缩放（`DynamicTypeMetrics.calendarSp`）；最大档下允许降到"只显示日号"（不显示农历），但不许裁切数字 |
| 触控目标 | 日格 ≥ 40dp 且整格可点；胶囊 40dp 高（**视觉 40 / 触控 48**，靠 `minimumInteractiveComponentSize` 撑） |

## 10. 与 iOS 的差异（逐条，都是有意）

| # | 项 | iOS | Android | 理由 |
| --- | --- | --- | --- | --- |
| 1 | 顶栏控件 | 玻璃胶囊（Liquid Glass） | outlined / elevated assist chip | Material 没有玻璃层 |
| 2 | 未来日期提示 | 玻璃 toast（且实际是**死代码**） | **Snackbar**（真的会弹） | M3 规范 + 修 iOS 缺陷 |
| 3 | 年态返回路径 | 只能点迷你月（左胶囊隐藏且不可点） | 左胶囊隐藏，但**系统返回键可用** | Android 用户习惯 |
| 4 | 右胶囊文案 | 恒为相对日 | 选中日不在当前月时改显具体日期 | 避免"看着 12 月却写着今天" |
| 5 | 平板横屏的年历 | **不可达**（强制收月态） | **同 iOS**：分栏时无年态、无周态 | 已由产品确认（2026-09-26）；看年视图请转回竖屏 |
| 6 | 底部导航 | 玻璃浮条（滚动时收起）+ 手工 `TabBarClearance` | `NavigationBar` 参与布局，不收起 | M3 无自动收起规范；结构上消除遮挡 |
| 7 | 6 行月份的最后一行 | 落在浮条之下（被遮住） | 不可能发生（底栏占真实高度） | 结构修正 |
| 8 | 分页器构建页数 | 3 页（a11y 元素重复） | `beyondViewportPageCount = 0` | a11y 正确性 |
| 9 | 农历字号来源 | `lunarFont` 与 `miniDayFont` 两套 | 同（保留两套） | 迷你月与月格的可用空间确实不同 |
