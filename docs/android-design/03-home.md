# 03 · 首页（三态日历）

> 首页是 **整屏三态 morph** 模型：`month`（月）→ `week`（周）→ `year`（年）。
> 全部几何取自 iOS `Views/Home/{CalendarLayout,CalendarPaneViews,HomeView}.swift`，单位换成 dp；
> 顶栏与底栏换成 Material 3。
>
> 证据：`docs/ios-reference/v3-home.md`（含 `file:line`）· 设计稿 [`mockups/png/02-home.png`](mockups/png)
> 代码：`ui/home/{HomeScreen,HomeViewModel,CalendarLayout,CalendarGrid,CalendarCanvas}.kt`

---

## 1. 状态机

```
                    ┌──────────────────────────────────────┐
                    │  month  （初始态，冷启动恒为此态）      │
                    └──────────────────────────────────────┘
                       │ 点任意日期              ▲ 点左胶囊（‹ 九月）
                       │（expand 0→1，滑动）      │（expand 1→0，滑动）
                       ▼                        │
                    ┌──────────────────────────────────────┐
                    │  week   （星期栏 + 周条 + 当日内容）    │
                    └──────────────────────────────────────┘

                    ┌──────────────────────────────────────┐
   点左胶囊 ‹2026年  │  year   （3 × 4 迷你月历）             │
   （zoom 0→1，缩放）└──────────────────────────────────────┘
        month ─────────────────────────────► year
              ◄─────────────────────────────
                点任意迷你月（zoom 1→0，缩放）
```

| 迁移 | 触发 | 动画 | 进度量 |
| --- | --- | --- | --- |
| 月 → 周 | **点任意日期** | 滑动 | `expand: 0 → 1` |
| 周 → 月 | 点顶栏左胶囊（`‹ 九月`） | 滑动 | `expand: 1 → 0` |
| 月 → 年 | 点顶栏左胶囊（`‹ 2026年`） | 缩放 | `zoom: 0 → 1` |
| 年 → 月 | 点任意迷你月 | 缩放 | `zoom: 1 → 0` |
| 任意 → 今年当月 | 点顶栏右胶囊（`今天`） | 年态：先 morph 回当月；月/周态：滚动到今天 | — |

> **平板横屏（分栏）例外**：分栏下只有月态。切进分栏时无动画收回月态，
> 年份入口随顶栏一起消失（对齐 iOS，见 §2.3、§3.4、§10 第 5 条）。

**必须遵守的三条状态规则**（iOS 踩过的坑）：

1. **可见性由 `mode` 决定，不由动画值决定。**
   年层"在不在"必须只从 `mode` 推出；`zoom` / `expand` 只负责过渡。
   违反这条的后果：配置变更（旋转 / 切深色）后动画值回到 0，年历整屏消失，只剩顶栏（v2 的 D2 缺陷）。
   **恢复时把进度量 `snapTo` 到终值**，不要让它停在 0。
2. **morph 进行中禁止输入。** `morphing = (正在 morph)` 期间：三层不重建、分页器 `disabled`、
   返回 / 点日期 / 今天三者全部 guard 掉。
3. **状态不持久化。** 冷启动恒为「今天 + 月态」。收到 `日记数据变更` / `UI 设置变更`
   （语言、主题、周起始、`auto_time`、导入备份）时重置回「今天 + 月态」。

### 1.1 显示态与"上次停留"无关

不要记住"用户上次在年态" —— 每次回到首页都是月态。理由：首页的核心动作是"看今天 / 点某天写日记"，
停在年态会让这个动作多两步。

## 2. 几何

### 2.1 竖屏（手机 · 平板竖屏同构）

```
┌──────────────────────────────────┐
│ statusbar                         │ 32
├──────────────────────────────────┤
│ ← 12dp 上边距                      │
│ [ ‹ 2026年 ]            [ 今天 ]  │ 52   ← 胶囊行，合计 64
│                                   │
│  九月                             │ 72   ← 大标题槽 BIG_TITLE_H
│  一 二 三 四 五 六 日              │ 30   ← 星期栏 WEEKDAY_H
│ ─────────────────────────────────│
│   1   2   3   4   5   6           │
│  二十 廿一 廿二 廿三 廿四 廿五       │ cellH = (区高 − 102) / 6
│  ...                              │ ← 恒除 6；5 行的月份下方留白
├──────────────────────────────────┤
│  日记   足迹   搜索   设置         │ 80   ← NavigationBar
├──────────────────────────────────┤
│              ▬                   │ 24   ← 手势条
└──────────────────────────────────┘
```

| 常量 | 值 | 说明 |
| --- | --- | --- |
| `TOPBAR_H` | **64** | 12dp 上边距 + 52dp 胶囊行。M3 small top app bar 的高度是 64，与 iOS 的 12+52 巧合一致 |
| `BIG_TITLE_H` | **72** | 大标题（`九月`）的槽位。**它同时是 morph 的终点**，不能改 |
| `WEEKDAY_H` | **30** | 星期栏 |
| `WEEK_STRIP_H` | **68** | 周态里那一行日期 |
| `DAY_TITLE_H` | **40** | 周态日期标题行（`9月26日 周六 丙午年八月十六`） |
| `YEAR_TITLE_H` | **62** | 年历的 `2026年` 标题块 |
| `YEAR_PAD` / `YEAR_SPACING` | **16 / 6** | 年历页边距 / 卡片间距 |
| `MINI_PAD` / `MINI_TITLE_H` | **6 / 17** | 迷你月卡片内缩 / 月份标题高 |

**日历区高度** = `可用高 − 64`，下限 320dp。
**格高** `cellH = (日历区高 − 72 − 30) / 6`。

> ### 为什么"恒除 6"？
> 因为 **5 行的月份（如 2026-09）要在下方留出一行的空白**。
> 若改成 `除以实际行数`，翻月时格子高度会在两个值之间来回跳，整块日历上下抖动。
> 留白好过抖动 —— 这条与 iOS 一致，**不要"优化"**。

**日号与农历字号**（跟着格高走，不写死）：

```kotlin
fun dayFont(cellH: Float)   = min(20f, max(13f, cellH * 0.34f))
fun lunarFont(cellH: Float) = min(11f, max(9f,  cellH * 0.18f))
```

> 写死 20 / 11 的后果：分栏或横屏把格子压到 40dp 时，日号和农历重叠。

### 2.2 平板（Medium · 800 × 1280 竖屏）

- 侧栏 96dp；剩余 704dp 内**日历限宽 640dp 居中**（`min(640, 内容宽)`）。
- 其余几何与手机**完全相同**（大标题 72、星期栏 30、恒除 6）。
- 三态 morph 与手机一致。

### 2.3 平板（Expanded · 1280 × 800 横屏，分栏）

```
┌────────┬───────────────────────────┬──────────────────────────────┐
│        │  九月  2026年              │ 34  ← 紧凑标题行              │
│  rail  │  一 二 三 四 五 六 日       │ 26  ← 紧凑星期栏              │
│  96dp  │  ─────────────────────    │                              │
│        │   1   2   3   4   5   6    │     9月26日 周六  丙午年…  [今天] │ 44
│        │   …                        │ ──────────────────────────── │
│        │   28  29  30               │  ┌────────────────────────┐  │
│        │                            │  │ 21:40                  │  │
│        │  ↕ 上下滑翻月               │  │ 字体样式自检            │  │
│        │                            │  └────────────────────────┘  │
└────────┴───────────────────────────┴──────────────────────────────┘
   ← masterWidth 260–440dp →          ← detailWidth ≥ 240dp →
```

| 常量 | 值 | 说明 |
| --- | --- | --- |
| `COMPACT_TITLE_H` | **34** | 分栏左栏的标题行（大标题 24sp） |
| `COMPACT_WEEKDAY_H` | **26** | 分栏左栏的星期栏 |
| 分栏间距 | **16.5dp** | 16dp 页边距 ×2 + 0.5dp 分隔线（实占） |
| 右栏标题行 | **44** | 比竖屏的 40 高 4dp，为了放得下「今天」胶囊 |
| 右栏正文列宽 | **max 560dp** | 分栏里再限一次宽，否则一行 100+ 字 |

**分栏下没有顶栏，也没有年态与周态**：切进分栏时无动画收回月态（对齐 iOS）。
左栏只有「上下滑翻月」与「点日期」两种交互；`今天` 在右栏标题行。

**密度降级**：左栏可用高不足时，月历自动降级为**周条**（只画选中日所在那一行）。
判据见 §5.3。

## 3. 顶栏胶囊行

两枚 M3 **assist chip**（40dp 高、full 圆角）：

| 位置 | 变体 | 标签 | 点击结果 |
| --- | --- | --- | --- |
| 左 | `outlined`（1dp `outlineVariant` 描边，`onSurface` 文字）+ 前导 `chevron_left` 20dp | 月态：`2026年`；周态：`九月`；**年态：整枚隐藏** | 月态 → 年态；周态 → 月态；年态 → 不可点 |
| 右 | `elevated`（`surfaceContainerLow` + `shadow-1`）+ 前导 `calendar_today` 18dp | 相对日文案（见下） | 回到今天（年态时先 morph 回当月） |

### 3.1 为什么是 chip 而不是按钮

iOS 用两枚玻璃胶囊。Material 里最接近"轻量、可点、带前导图标"的组件就是 **assist chip**：
左侧那枚是导航（outlined，中性），右侧那枚是动作（elevated，微微浮起，读作"可点的动作"）。
**不要**用 `FilledTonalButton`（太重，会把首页主色抢走），也不要用 `TextButton`（没有容器，在日历上方会飘）。

### 3.2 年态为什么隐藏左胶囊

iOS 在年态把左胶囊 `opacity 0` 且 `allowsHitTesting(false)`。Android **照做**，但**必须**同时提供另外两条退路：

- **系统返回键**：年态 → 月态（`PredictiveBackHandler`，见 `02-adaptive-and-navigation.md` §6）；
- **点任意迷你月** → morph 回该月。

> 不能只留"点迷你月"一条路（iOS 那样），因为 Android 用户在满屏无返回按钮时第一反应是系统返回键。

### 3.3 右胶囊的文案（**Android 的一处改进**）

```
if (选中日 属于 当前显示的月)  label = 相对日(选中日)      // 今天 / 昨天 / 明天 / 3 天前 …
else                          label = 具体日期(选中日)     // 9月26日
```

**为什么**：iOS 竖屏翻月**不改选中日**（§6.2）。于是可能出现"屏幕上是 12 月、胶囊却写着『今天』"的误导。
Android 保留"翻月不改选中日"这个行为（它保证翻月纯粹是浏览，不会意外改变目标日期），
但让胶囊在两者脱节时说实话。

相对日文案表（与 iOS `L10n.relativeDayLabel` 对齐）：

| 差值 | 文案 |
| --- | --- |
| 0 | 今天 |
| −1 / +1 | 昨天 / 明天 |
| −2 … −6 / +2 … +6 | N 天前 / N 天后 |
| 其它 | 具体日期（`9月26日`） |

### 3.4 分栏时整条胶囊行隐藏

平板横屏分栏时**没有这一行**：整条隐藏。`今天` 收进右栏标题行，**严格一处**，
不允许两处同时出现（v2 的 D9 就是这个重复）。**年份入口也随之消失** —— 分栏下年态不可达（§2.3、§10）。

## 4. 月态

### 4.1 一格画什么

```
        ┌─────────────┐
        │     26      │  ← 日号：dayFont，tabular-nums
        │    十六      │  ← 农历：lunarFont，onSurfaceVariant（仅中文 + 有空间时）
        │    ▬▬        │  ← "有日记"标记：min(20, cellW×0.5) × 2dp 圆角横线，主色
        └─────────────┘
          ↑ 选中/今天：圆
```

### 4.2 四个状态的**完整**表达（颜色 + 非颜色）

| 状态 | 非颜色表达 | 颜色 | 优先级 |
| --- | --- | --- | --- |
| **今天** | **1.5dp 主色圆环**（不是实心） | 圆环 `primary`；日号与农历 `primary` | 2 |
| **选中** | **主色实心圆** | 底 `primary`；日号与农历 `onPrimary` | 1（最高） |
| **有日记** | 日号下方 **2dp 主色短横线**，宽 `min(20, cellW × 0.5)` | `primary` | 3 |
| **未来日期** | 日号与农历一律 `onSurfaceVariant`（**不用 alpha**：0.35 的对比度只有 2.19:1，违反 WCAG AA） | `onSurfaceVariant` | 4 |

- 圆直径 `circleD = min(cellW − 3, 内容高 + 14, cellH − 3)`。
- **今天与有日记可以共存**（裁决 #8）：今天画圆环，同时画短横线。
  但**选中时不再画短横线**（实心圆上的横线看不清）。
- **未来日期用语义色 `onSurfaceVariant`**（iOS 是整格 `alpha × 0.35`，那样对比度只有 2.19:1，R3 实测后已改）。
  我们也不画周末列的配色，所以"和周末混淆"的顾虑不存在。
- **相邻月的日期一律不画**（`showAdjacent = false`）：格子留空、不可点、不进无障碍树。
  画相邻月日期会让"这个月"的边界消失（v2 的 D4）。

### 4.3 行与分隔线

- 每行顶部 1dp `outlineVariant` 分隔线，**第一行不画**。
- **整行都不属于当月时不画分隔线**（v2 的 D12）。
- 网格**顶格对齐**紧贴星期栏，剩余高度形成底部留白（§2.1）。

### 4.4 星期栏

- 文案来自 `AppSettings.week_start`（`周一` / `周日`），纯文本，13sp，`onSurfaceVariant`。
- **周末列不做特殊配色**（iOS 也没有）。首轮给周末列加了 `onSurfaceVariant @60%`，对比度只有 3.16:1，已回退。

## 5. 周态与年态

### 5.1 周态（竖屏 / 平板竖屏）

```
星期栏（30）
周条（68）           ← 只有选中日所在的那一周，7 格
──────────────────
日期标题行（40）      `9月26日 周六`    `丙午年八月十六`      [今天]
──────────────────
当日内容（剩余高度，可滚动）
```

- 周条格：日号 20sp + 农历 11sp；选中 = 实心圆；有日记 = 短横线；**不画分隔线**。
- 当日内容（`DayContentView`）：
  - 有片段 → 每段一张卡片（时间 `schedule` 14dp + 地点 `place` 14dp + 富文本）；
    若选中日是**今天**，末尾追加一枚 filled 按钮「继续写今天的日记」。
  - 没有片段 → 空态：`edit` 图标 28dp（未来日换 `dark_mode`）+ 文案 + （仅当非未来日且是今天）「写日记」按钮。
  - 内容左右内边距 20dp，顶部 18dp，底部 96dp（让最后一张卡能滚出底栏）。
- **左右滑翻周**：翻的是"选中日所在周"，位移量 = 两周相差的天数，选中日跟着走。

### 5.2 年态（竖屏 / 平板竖屏）

```
2026年                        62   ← 大标题
┌────────┬────────┬────────┐
│ 1月     │ 2月     │ 3月     │
│ 一二三四五六日 …        │      cardH = (区高 − 62 − 8 − 18) / 4
├────────┼────────┼────────┤
│ 4月     │ 5月     │ 6月     │
…
```

| 项 | 值 |
| --- | --- |
| 列数 × 行数 | **3 × 4** |
| 日历/年历最大宽度 | **640dp**（竖屏与平板竖屏；分栏时改走 `masterWidth`） |
| 卡片宽 | `(宽 − YEAR_PAD×2 − YEAR_SPACING×2) / 3` |
| 卡片高 | `(区高 − YEAR_TITLE_H − 8 − YEAR_SPACING×3) / 4` |
| 卡内 | `MINI_PAD 6` 内缩；月份标题 `MINI_TITLE_H 17`；下方 6 行 × 7 列迷你格 |
| 迷你日号字号 | `min(14, max(9, min(cellW × 0.95, cellH × 0.5)))` |
| **迷你月里不画农历** | iOS `miniLunarHidden = 0` |
| 迷你月里不画分隔线 | 同 |

迷你格状态：**有日记** = 日号加粗 + `primary`；**今天** = 实心圆（`primary` 底 + `onPrimary` 字）；
**选中日所在的那个月**的卡片给一层轻微高亮（`surfaceContainerHigh` 底）—— 这是 Android 加的，用来回答"我现在在哪个月"。

- **上下滑翻年**（不是左右）。
- 点卡片 → 缩放 morph 回该月。
- 卡片整块可点，涟漪**有界**（用 `Modifier.clip(shape)` + 默认 indication，不要 `indication = null`）。

### 5.3 密度降级（只在空间真的不够时触发）

```
perRow = floor(可用高 / 行数)          // 行数 = displayedWeeks().count（去掉末尾整周非本月的填充行）
perRow >= 60  → 显示农历
perRow >= 38  → 不显示农历
否则          → 降级为「周条」（只画选中日所在行）
```

- **行数必须传"实际要画的行数"**，不能传固定的 6。否则"5 行放得下"会被误判成"6 行放不下"，
  平板横屏于是错误地降级成周条（iOS 踩过这个坑）。
- 降级时 `cellH` 被夹回 `WEEK_STRIP_H`，否则会出现一行 200dp 高的巨大日期。

## 6. 手势

| 手势 | 位置 | 结果 |
| --- | --- | --- |
| **上下滑** | 月态月格区域 | 翻月（上一月 / 下一月）。**翻月不改选中日** |
| **上下滑** | 年态 | 翻年 |
| **左右滑** | 周态周条区域 | 翻周。**选中日跟着位移**（保持"周几"不变） |
| **上下滑** | 平板横屏左栏 | 翻月。**把选中日带到新月份的同一天**（夹到该月最后一天） |
| **点日期** | 月态 | 竖屏/平板竖屏 → morph 进周态；**平板横屏 → 只换选中日** |
| **点日期** | 周态 | 换选中日，不 morph |
| **点左胶囊** | 月态 / 周态 | 年态 / 月态 |
| **点右胶囊** | 任意 | 回今天 |
| **点迷你月** | 年态 | morph 回该月 |
| **长按** | 任意 | **无**（iOS 也没有） |
| **捏合** | 任意 | **无**（见 `README.md` 有意分歧） |

### 6.1 跟手与回弹

翻页跟手，松手后按阈值决定去留：

```
翻下一页：predictedEnd < −90dp  或  (位移 < 0 且 |位移| > 60dp)
回弹：    rubber(x) = c · x / (x + c)，c = pageSize × 0.25
```

### 6.2 翻月为什么不动选中日（竖屏）

竖屏月态里**选中日不可见**（除非它正好落在当前月）。所以"翻月"是一次纯浏览动作，
不该悄悄改变"我要写哪一天"的目标。选中日在点日期时才改变。

> 唯一的副作用是顶栏胶囊可能显示与当前月无关的日期 —— 已由 §3.3 的文案规则解决。

平板横屏**相反**：右栏常驻显示选中日的内容，翻月若不动选中日，右栏就会显示"另一个月的某天"，
与左栏脱节。所以横屏翻月要把选中日带到新月份的同一天。

### 6.3 未来日期

点未来日期**不打开编辑器**，只给一条 Snackbar：`这一天还没到，不能写日记`（带「知道了」动作）。
未来日的空态用 `dark_mode` 图标 + 「这一天还没到」，且**不提供**写入按钮。

## 7. morph 几何

> **逐帧分解图见 [`mockups/png/08-flows.png`](mockups/png) 第 2、3 节** —— 实现时直接对着比对。

morph 的每一个端点**必须取自真实排版用的同一个矩形、同一组常量**。任何"再算一遍"都会在收尾时跳一下。

### 7.1 月 ↔ 周（滑动，`expand: 0 → 1`）

| 图层 | 起点（月态） | 终点（周态） |
| --- | --- | --- |

### 7.2 月 ↔ 年（缩放，`zoom: 0 → 1`）

| 图层 | 起点 | 终点 |
| --- | --- | --- |

### 7.3 动画参数

| 项 | 值 |
| --- | --- |
| 时长 | **400ms** |
| 缓动 | `easing.emphasized` = `CubicBezierEasing(0.2f, 0f, 0f, 1f)` |
| 月↔年 与 月↔周 | **共用同一条曲线**（iOS 的 `morphAnimation == morphSlideAnimation`） |

## 8.6 翻页的"邻页"是个**独立的页面**（踩过坑）

跟手翻页会在当前页的上下各组合一张邻页。邻页的参数是 `calendarArgs.copy(…)` 造出来的，
**必须逐个字段确认"它跟不跟着月份走"**：

| 字段 | 邻页 | 为什么 |
| --- | --- | --- |
| `displayed` / `monthFirst` | **换** | 网格本身 |
| `monthTitleLabel` | **换** | ⚠️ 漏了它 = 滑进来的十月**顶着「九月」的标题**。用户第一眼就是"下一个月显示的其实是当前月" |
| `rowOffsets` / `rowAlphas` / `rowMetrics` | **重置** | morph 相关，邻页不参与 |
| `selectedWeekIndex` | 置 -1 | 同上 |
| `metrics` / `cellHeight` / `calendarW` / `weekStart` / `showLunar` | 沿用 | 只跟尺寸与设置有关 |
| `selectedKey` / `todayKey` / `flags` | 沿用 | 全局状态 |

**教训**：`data class.copy()` 很顺手，但它默认"什么都不变"——
凡是**跟着业务坐标走**的字段（这里是"哪个月"）都必须显式覆盖。
年历那一侧反而没这个问题，因为 `YearLayer(year = year + offset)` 的年份是**构造参数**，
不存在"忘了换"的可能。**能用构造参数表达的就别用 copy。**

**固定检查项（写进验证流程）**：拖到一半时截图，确认**屏幕上下露出来的那一页
是不是真的相邻月/相邻年，标题与日期都要对**。只看"offset 有没有生效"是不够的 ——
这个 bug 就是 offset 正常、内容也对、只有标题没换。

## 8.7 月态翻页：**连续无限滚动**（2026-09-26 用户提议，**已实施**）

### 结果（已落地）

三种视图（月 / 周 / 年）的翻页**语义完全一致**，都是"框架滚动 + 官方吸附"：

| 视图 | 容器 | 吸附 |
| --- | --- | --- |
| 月 | `LazyColumn`（2412 个月） | `rememberSnapFlingBehavior` |
| 周 | `LazyRow`（居中窗口 7 周） | 同上 |
| 年 | `LazyColumn`（201 年） | 同上 |

手写分页器（`PagerViewport`）、自绘翻页手势、位移与橡皮筋、收尾动画**全部删除**。

**它解决了**（都是磨了很多轮、且每次修一处冒一处的问题）：
邻页顶着当前月标题 / 两页之间空洞 / 邻页只露出一部分（盒子与内容错位） /
拖动顿挫（UI 线程 27% 卡顿）。
**并且天然适配不同高度的屏幕** —— 内容多高就多高，不必按屏幕反推"一页该多少 dp"。

### 为什么当时该改

当时的月态是一个**手写的分页器**：`PagerViewport` 同时组合"上一页 / 当前页 / 下一页"，
用 `graphicsLayer { translationY }` 整体位移，自己算页高、自己算可拖范围、
自己做橡皮筋与收尾动画。这条路已经连续踩了七个坑，且每次修一处就冒一处：

- 邻页顶着当前月的标题（`copy()` 漏换字段）
- 两页之间的空洞（页高跟内容变）
- 邻页只露出一部分（盒子与内容错位 —— 至今没查清）
- 拖动顿挫（UI 线程 27% 卡顿，`graphicsLayer` 的 block 属**布局阶段**读取）

**根因是"我在用手写代码复刻框架已经做好的事"。**

### 改法（用户提议）

把月视图做成**一张连续的、可无限上下滚动的列表**：
一个月一项，项与项之间留一行空白；滚动是**无级**的（像滚一张长纸），
松手时由框架吸附到最近的一个月。

```kotlin
val listState = rememberLazyListState(initialFirstVisibleItemIndex = monthIndex)
LazyColumn(
    state = listState,
    // 官方吸附：惯性 + 吸附到 item 边界，不需要自己写收尾动画
    flingBehavior = rememberSnapFlingBehavior(listState),
    // morph 期间禁用滚动（规范 §1 规则 2）
    userScrollEnabled = !morphing,
) {
    items(CalendarGrid.MONTH_KEYS.size) { index -> MonthBlock(index) }
}

// 停稳后同步 monthKey（带动画结束与 fling 结束）
LaunchedEffect(listState) {
    snapshotFlow { listState.firstVisibleItemIndex }
        .collect { monthKey = CalendarGrid.MONTH_KEYS[it] }
}
```

### 这一改删掉的东西（全部是手写的）

| 删除 | 原因 |
| --- | --- |
| `PagerViewport`（裁切 + 位移 + 邻页三件套） | `LazyColumn` 自己渲染相邻项 |
| `pageOffset()` / `dragOffsetPx` / `settleAnim` | 滚动位置由 `LazyListState` 持有 |
| `neighborMonthArgs()` | 不存在"邻页参数"这回事了 |
| `monthPageH` / `dragRangeDp` / `clampOffset` / `rubberBand` 的翻页用途 | 框架的 fling 物理 |
| 分页收尾动画（`PAGE_SETTLE_MS` / `PAGE_CANCEL_MS`） | `rememberSnapFlingBehavior` |

### 顺带修好的

- **跟手与卡顿**：滚动走框架的优化路径，1:1 跟手 + 惯性；不再有"邻页在拖动中途才被组合"的长帧
- **邻页空白 / 错位**：不存在"我自己摆两页"这回事
- **首尾边界**：列表两端自然到头，不需要 `hasNext/hasPrev`

### 要保持不变的

- **月↔周 morph**：仍然发生在**当月那一项内部**（选中行上移到周条位置），
  morph 期间 `userScrollEnabled = false`
- **月↔年 morph**：月层整体缩放/淡出到年历；源矩形改用"当月项的当前矩形"
- **周态 / 年态**：不受影响
- **分栏**：左栏同样用这个列表（`userScrollEnabled` 保持可滚）
- **吸附后 `monthKey` 才变**（与现在的"松手后提交"语义一致）

2. **非线性布局的补偿要用 `offset`，不能用 `padding`**。农历上提 6dp 之后，

3. **`DiaryMark` 必须始终占位**。原来只在 `hasDiary` 时才组合，
   有日记的格子整体比别的格子高 3dp，一排看过去是不齐的。

### 当初定的实施要点

1. **钉住层**放在 `Box` 里、声明在列表**之后**（画在上面），带 `surface` 背景色 ——
   否则滚动的日期会从标题底下透出来。
2. **大标题的字**跟着滚动连续更新（取"当前顶部那一周所属的月"），
   不是等吸附完成才换 —— 参考图里标题是在滑动过程中就换掉的。
3. **所有**月份块都变成紧凑形态（无大标题、无星期栏），只留

4. **morph 的落点不变**：钉住层里的星期栏就是月↔周 morph 的终点，

5. ⚠️ **不能只做第 3 条**：试过"只把其他月份改成紧凑标签、不钉住标题"，

## 8.9 竖屏行高：**由列宽推出**，不是把整页均分（2026-09-26 用户反馈）

用户："目前的日期上下间隔太大了，参考左右间隔来设置上下间隔。"

```kotlin
fun dayCellHeightFor(calendarW: Float, fontScale: Float, showLunar: Boolean): Float {
    val byWidth = calendarW / 7f * CELL_H_PER_COL_W        // 列距 × 1.2
    val byContent = (if (showLunar) 72f else 48f) * max(1f, fontScale)
    return max(byWidth, byContent).coerceIn(MIN_CELL_H, SANITY_MAX_CELL_H)
}
```

两条规则，**取大者**：

1. **列距 × 1.2** —— 上一次改成"把整页均分给行数"之后，5 行月的行距达到 114dp，
   是列距（约 51dp）的两倍多，看着很散。iOS 参考图约 1.34，设计稿的
   `PORTRAIT_CELL_H = 56` 对应约 1.1，取中间的 1.2。
2. **内容下限 72dp** —— `CalendarDayCell` 的注释写明"日号 + 农历 ≈ 70dp"。
   只按列宽（61dp）会**裁掉农历**（真机实测农历被切一半）。无农历时用 48dp（圆直径那档）。

**行高与字号的关系**：字号是从 `cellH` 推出来的（`dayFont = cellH × 0.34` 上限 20、
`lunarFont = cellH × 0.18` 上限 11），所以两者必须**同源** —— `metrics` 用的是同一个
`cellH`，改行高时字号会跟着走，不会脱节。

**日号与农历之间的空档**：日号底下的圆（直径 = `min(cellW−3, 内容高+14, cellH−3)`）
比数字本身高一大截，农历因此离得远。农历上提 `LUNAR_TIGHTEN = 6dp`，
Column 再用 `offset(y = +3dp)` 补偿半个量做**光学居中**（相对分隔线上下居中）。

## 8.9.1 morph 的时长与曲线（2026-09-26 用户："400ms 太快了"）

**对齐 iOS**（`CalendarLayout.swift:133-152`）：

```swift
static let morphDuration: Double = 0.6                 // 600ms
static var morphSlideAnimation: Animation {
    .timingCurve(0.2, 0.75, 0.3, 1.0, duration: morphDuration)
}
```

| | 时长 | 曲线 |
| --- | --- | --- |
| iOS | **600ms** | `(0.2, 0.75, 0.3, 1.0)` |
| Android 曾用 | ~~400ms~~ | ~~`emphasized` = `(0.2, 0, 0, 1)`（慢起步）~~ |
| Android 现在 | **600ms** | `emphasizedDecelerate` = `(0.05, 0.7, 0.1, 1)` |

**600ms 不违反 Material**：它就是 M3 的 `long4` 令牌，而 M3 自己写着
"larger, more complex transitions 用更长的时长" —— 全屏、多元素、带内容位移的
morph 正属此类。

**曲线也要对**：`emphasized`（慢起步）会让开头 1/4 时间只走完约 13% 的进度，
观感是"开头一段几乎不动、然后突然快起来"。iOS 的注释专门讲过这一点
（"此前用 easeInOut……观感上就比月↔周切换慢半拍"）。
`emphasizedDecelerate` 是 M3 令牌里"起步带速度、尾部减速"的那条，意图与 iOS 一致。

## 8.9.2 跨月点击进入周态时上移错误的那一行（**已用吸附规避**）

**当前决定（用户 2026-09-26）**："那我退而求其次，你把吸附功能加上去吧。
这样每次都会是默认位置了。"

月列表恢复**吸附**（`rememberSnapFlingBehavior` + "停稳后若不在项起点就拨回去"的兜底，
后者是必须的：慢拖没有 fling，框架不会自动吸）。静止态因此**永远是某一项的起点**，
`monthKey` 恒等于顶部那一块 ⇒ morph 的行号不会串月 ⇒ 触发不了下面这个缺陷。

下面保留根因分析，供将来真正修好时参考（真正干净的做法是拆开 `monthKey` 的两个职责，
见本节末尾）。

---

用户（2026-09-26）

用户（2026-09-26）："当月视图不是默认位置的时候，因为现在是无级滑动的，导致，
点击日期的时候，进入周视图后的并不是点击的日期的周，似乎是默认月视图下的点击所在位置的日期。
这是个严重的 Bug。"

### 已用 `uiautomator dump` 确认的事实

1. **命中测试是对的**：滚动后 dump 里各格的 `bounds` 会跟着滚动量走
   （9月15日 从 `[945,1143]` 移到 `[532,701]`，与 400px 的滑动一致），
   点 (232,648) 正好落在它里面，选中的也是它 ✓
2. **在本月内滚动后点击也是对的**：滚一点 → 点 9月15日 → 周条显示 **14–20**
   （含 15 日的那一周）✓
3. **只有"点的那一天不属于 `monthKey` 那个月"时才错**。

### 根因

`monthKey` 只在滚动**停稳**后更新（`monthListState` 的 `snapshotFlow`）。
于是"滚到十月的日期上直接点"时它还是九月，而 morph 的
`selectedWeekIndex` 是拿 **`monthKey` 那个月**的周列表算出来的 ——
**用九月的行号去驱动十月的块 ⇒ 上移的是错误的那一行**。
观感正是用户说的"默认月视图下那个位置的日期"。

### 尝试过的修法与它的问题（下次别重蹈）

**试法**：点击时把 `monthKey` 同步到被点那天所属的月。

- ✅ 选中变对了（dump 确认选中 10月1日）；
- ❌ 但**第二次点击进不了周态** —— 内容在两次点击之间被移动了，
  第二次点落到了别的格子上。

原因：原先有 `LaunchedEffect(monthKey) → scrollToItem`，改 `monthKey` 就触发滚动。
已把滚动改成**显式**（只有"回到今天 / 年历选月 / 从周态返回"才滚），
但第二次点击仍然失败 ⇒ **还有第二个跟着 `monthKey` 走的东西没找出来**。

**下次的做法**：不要再让 `monthKey` 兼两个职责（"列表滚动位置"与"morph 的目标块"）。
应把 morph 的输入全部改成从**选中日所属的月**派生（`selectedMonthKey`），
让 `monthKey` 只表示滚动位置。这样点击不改变滚动、morph 也拿到正确的行号。

⚠️ 本次改动已 `git checkout` 回退，未提交半成品。

## 8.10 ⚠️ 三个 morph 回归（月视图重构引入，2026-09-26 用户实测）

用户："周视图返回月视图的时候，动画没有正确返回，会有跳变。年视图在切换的时候，
动效会出现在切换后的月份。月视图到年视图的切换也存在跳变，是月视图消失的问题。
这几轮特别是月视图的重构导致的问题。"

### 共同根因：**"紧凑形态"的判据挂在了 morph 进度上**

```kotlin
// 现在的写法（有问题）
val compact = !(withMorph && p > 0.01f)      // p 只看了 weekProgress
```

紧凑块（34dp 小标签）与完整块（72dp 大标题 + 30dp 星期栏 = 102dp）**高度差 68dp**，
而这个判据是**连续量** `p` 的函数 —— 于是每跨过 0.01，那一块的高度就突跳一次。

| 现象 | 机制 |
| --- | --- |
| 周 → 月返回跳变 | p 回落到 0.01 时，当前块 102dp 瞬切 34dp，跳 68dp |
| 年态切换动效落在"切换后的月份" | 判据**只看 `weekProgress`**，而年 morph 期间它恒为 0 ⇒ 当前块保持紧凑，年 morph 的源几何（按 102dp 算）与实际不符 |
| 月 → 年跳变、"月视图消失" | 同上：源矩形错位，月层在错误的几何上淡出 |

**已修**：判据同时看 `weekProgress` 与 `yearProgress`（年 morph 期间恢复完整几何，
即回到重构前那套能工作的几何）。这是一处**实现错误**，不是取舍。

### 已用逐帧录屏**拍到**这个突跳（2026-09-26）

真机 `screenrecord`（30fps）+ `ffmpeg` 抽帧，月→周过程（第 62~73 帧）：

| 帧 | 画面 |
| --- | --- |
| 62–65 | 月态：大标题「九月」+ 星期栏 + 整月网格 |
| **66** | **大标题消失、网格整体上跳，首行 1-6 紧贴星期栏** ← 这就是突跳 |
| 67–71 | 网格各行再移动到周条的落点 |
| 72–73 | 周态：周条 + 当日面板 |

第 66 帧正是 `p` 刚跨过 0.01 的那一帧：块从"完整形态"（72 + 30）瞬切成"紧凑形态"（34），
**大标题消失、网格上移 68dp**。用户说的"跳变 / 月视图消失"就是它。
证据：`docs/ui-audit/r5-32-morph-frame-by-frame.png`。

### 仍未解决：周 ↔ 月自身的 68dp 突跳

只要"紧凑块"与"完整块"高度不同，且切换点由 `p` 决定，就一定会突跳 ——
把切换点挪到 p = 0 / p = 1 也只是把跳变挪到首尾帧。

**正确做法（下一轮，需真机逐帧验证）**：让**钉住层参与 morph**，月份块**永远紧凑**。

1. 所有月份块**恒定紧凑**（34dp 标签 + 网格）⇒ 高度永远一致 ⇒ 既没有突跳也没有"停稳闪一下"；
2. 钉住层负责 morph 的头部：大标题按 `alpha = 1 - 2p` 淡出、**高度随 p 折叠**；
   星期栏保持在顶部不动（它就是 morph 的终点位置）；
3. 当前块的行位移量由 `bigTitleH * p` 改为 **`(钉住层标题高 + 星期栏高) * p`**，
   让选中行落到钉住星期栏之下；
4. `LazyColumn` 需要 `contentPadding(top = 钉住层高度)`，否则首行会被钉住层盖住。

### 验证方式（**已打通**，这是本轮最有价值的产出）

这台机器 `screencap` 会返回**黑帧**（应用正常渲染：`uiautomator dump` 有 145 个节点、
`mCurrentFocus` 就是本应用、无 FLAG_SECURE）。改用：

```bash
adb -s <serial> shell screenrecord --time-limit 6 --size 540x1170 /sdcard/m.mp4
adb -s <serial> pull /sdcard/m.mp4 /tmp/m.mp4
/opt/homebrew/bin/ffmpeg -y -i /tmp/m.mp4 -vf fps=30 /tmp/frames/f%03d.png   # 本机有 ffmpeg
```

**动画类问题必须这样逐帧看** —— 6fps 会整段错过（第一次抽 15 帧就漏掉了过渡），
30fps 才抓得到那一帧。

## 10. 与 iOS 的差异（逐条，都是有意）

| # | 项 | iOS | Android | 理由 |
| --- | --- | --- | --- | --- |
| 1 | 顶栏控件 | 玻璃胶囊（Liquid Glass） | outlined / elevated assist chip | Material 没有玻璃层 |
| 2 | 未来日期提示 | 玻璃 toast（且实际是**死代码**） | **Snackbar**（真的会弹） | M3 规范 + 修 iOS 缺陷 |
| 3 | 年态返回路径 | 只能点迷你月（左胶囊隐藏且不可点） | 左胶囊隐藏，但**系统返回键可用** | Android 用户习惯 |
| 4 | 右胶囊文案 | 恒为相对日 | 选中日不在当前月时改显具体日期 | 避免"看着 12 月却写着今天" |
| 5 | 平板横屏的年历 | **不可达**（强制收月态） | **同 iOS**：分栏时无年态、无周态 | 已由产品确认（2026-09-26）；看年视图请转回竖屏 |
| 6 | 底部导航 | 玻璃浮条（滚动时收起）+ 手工 `TabBarClearance` | `NavigationBar` 参与布局，不收起 | M3 无自动收起规范；结构上消除遮挡 |
| 7 | 6 行月份的最后一行 | 落在浮条之下（被遮住） | 不可能发生（底栏占真实高度） | 结构修正 |
| 8 | 分页器构建页数 | 3 页（a11y 元素重复） | `beyondViewportPageCount = 0` | a11y 正确性 |
| 9 | 农历字号来源 | `lunarFont` 与 `miniDayFont` 两套 | 同（保留两套） | 迷你月与月格的可用空间确实不同 |
