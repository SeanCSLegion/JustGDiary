# 05 · 搜索 · 足迹 · 设置

> 三屏共用一套骨架：**页头大标题 + 筛选芯片条 + 内容区**。
> 它们的共同要求是：**筛选条件随时可见、可逐条撤销；空态必须给出路。**

## 一、搜索

### 1.1 结构（竖屏）

```
搜索                                    [找到 3 条日记]      ← 页头 28sp + 计数徽标
┌────────────────────────────────────┐
│ 🔍 搜索日记内容…              ✕ 取消 │ 56   ← SearchBar（常驻）
└────────────────────────────────────┘
┌────────────────────────────────────┐
│ 时间范围                            │
│ [全部时间] [本周] [本月] [今年] [自定义] │      ← FilterChip 组
│ 地点                                │
│ [全部地点] [📍中国 · 上海市]          │
└────────────────────────────────────┘
[上海 ✕] [本月 ✕] [中国 · 上海市 ✕]      ✕   ← 条件摘要（仅当有条件）
──────────────────────────────────────
（结果列表 / 空态 / 加载态）
```

### 1.2 搜索框（M3 `SearchBar` 语义，但**常驻**）

| 状态 | 表现 |
| --- | --- |
| 默认 | 56dp 高、full 圆角、`surfaceContainerHigh` 底；左 `search` 22dp；占位「搜索日记内容…」16sp |
| 有内容 | 右侧出现 `close` 清除按钮（40dp 触控） |
| 聚焦 | 右侧**追加**「取消」文字按钮（`primary`，14sp medium）；点它清空并收键盘 |
| 提交（软键盘 Search） | trim → 输入清空 → 加入已提交关键词列表（去重）→ 立即搜索 |

- **不做"折叠胶囊 → 展开输入框"的二段式**（iOS 也没有）。输入框始终整宽。
- 输入防抖 **250ms**；多关键词以空格分隔，**AND** 语义。
- **不要**用 iOS 那套 `.searchable` 的滚动联动收起（它在列表短的时候会抖）。若要收起，规则见 §1.5。

### 1.3 条件面板

| 组 | 选项 | 选中态 |
| --- | --- | --- |
| **时间范围** | 全部时间 / 本周 / 本月 / 今年 / 自定义 | 单选；「自定义」带起止日期时标签显示 `9月1日 – 9月30日` |
| **地点** | 全部地点 / 选择地点… | 「选择地点…」选中后标签变成 `中国 · 上海市` |

- 竖屏：两组上下排列；**平板横屏**：两组左右并排（省约 60dp 高度），且整块移入左侧筛选栏。
- 「自定义」→ ModalBottomSheet（§1.6）。

### 1.4 条件摘要行（**唯一的条件展示位**）

- 只在 `有关键词 或 有筛选` 时出现。`minHeight 44dp`。内容 = 可横向滚动的一排 `InputChip`（每个带 `close`）+ 右侧固定的「清除全部」图标按钮。
- 顺序固定：**未提交的输入 → 已提交关键词（按加入顺序）→ 时间 → 地点**。
- 点某个 chip 的 `✕` = 撤销该条件并立即重搜（关键词 chip 同时收键盘）。
- **平板横屏时不显示这一行**（左栏的 chip 组已经表达了全部条件）。

### 1.5 状态机

```
无关键词 && 无筛选        → 引导空态（「搜索你的日记」）
正在执行搜索              → LinearProgressIndicator(4dp) + 骨架行（3 组）
有结果                    → 结果列表（每页 200 条，滚动到底加载下一页）
无结果                    → 「没有找到匹配的日记」+「清除全部条件」按钮
索引未就绪（首次建索引）   → 「正在准备搜索索引…」+ 不确定进度
```

**三条必须做对的地方**（iOS 的缺陷）：

1. **索引未就绪 ≠ 无结果**。只有真正在重建索引时才置位 `indexNotReady`；
   空查询分支写 `total = 0`，**不要**写 `-1`（v2 的 D1：搜索页永远停在"正在准备搜索索引…"）。
2. **加载态必须可见**。iOS 的加载分支是死代码，搜索进行中列表空白。Android 用进度条 + 骨架屏。
3. **撤销条件必须使在途请求失效**（递增 `searchId` / `Job.cancel`），否则旧结果会写回。

### 1.6 两个 ModalBottomSheet

| 面板 | 内容 | 底部动作 |
| --- | --- | --- |
| **自定义时间范围** | 三个快捷胶囊（本周 / 本月 / 今年）+ 起止两个日期选择（默认本月 1 日 ~ 今天） | 清除 / 确定 |
| **选择地点** | 搜索框（**走 SQL `LIKE` 查询，不截断**）+ 地点清单（按记录条数降序，显示每项条数）+ 「未记录地点 · N 篇」 | 取消 / 确定 |

**「未记录地点」是一个独立选项，不是地点。** 选中它 = 筛选 `locText` 为空、`country` 等全空的片段。

### 1.7 结果列表项

```
┌────────────────────────────────────────────┐
│ [9月8日 周二]  21:40            上海 · 浦东新区 │ ← 日期胶囊 primaryContainer 13sp
│ 字体样式自检                                 │ ← 16sp，命中词 primaryContainer 高亮
│ 这一段是正文，用来和下面的标题对比字号。        │ ← 14sp onSurfaceVariant，2 行
└────────────────────────────────────────────┘
```

- 整行可点 → 打开该天的日记（阅读态）。
- 高亮：命中词包一层 `primaryContainer` 底色（**不用加粗、不用变色**），与页内搜索的高亮样式一致。
- 摘要来自 FTS `snippet()`，最多 2 行。

### 1.8 平板横屏

| 区域 | 宽度 | 内容 |
| --- | --- | --- |
| 左栏 | 340dp 固定 | 搜索框 + 条件面板（两组并排）+ 结果计数 |
| 分隔线 | 1dp | `outlineVariant` |
| 右栏 | 剩余 | 结果列表 |

筛选**常驻可见**，不需要再开面板；条件摘要行省略。

## 二、足迹

### 2.1 结构（竖屏）

```
足迹                          已标注 14 处 · 未记录 3 篇   ← 页头 + 一行摘要
[全部] [2026] [2025] [2024] [自定义]                    ← 年份芯片条（倒序）
┌──────────────────────────────────────────────────┐
│   7      9      4      14     13                 │   ← 5 格统计
│  省市    城市    国家    片段    天数                │
└──────────────────────────────────────────────────┘
┌──────────────────────────────────────────────────┐
│ 年度记录天数                                       │
│ 6 ┤        ██                                    │   ← 柱状图（仅 ≥2 个年份时出现）
│ 2 ┤  ██    ██    ██                              │
│ 0 └──2024──2025──2026─────────────────────────── │
└──────────────────────────────────────────────────┘
┌──────────────────────────────────────────────────┐
│ 地点清单                                          │
│  ▸ 🌐 中国                                    9  › │   ← 三级树
│      ▾ 📍 上海市                              6  › │
│          浦东新区                              4   │
└──────────────────────────────────────────────────┘
```

### 2.2 年份选择器

- 「全部」+ **有地点记录的年份（倒序）** + 「自定义」。
- 年份集合**只统计有地点的行，且不受当前筛选影响**（否则选了年份后其它年份会消失）。
- 「自定义」→ 与搜索页**完全同构**的时间范围面板。

**筛选叠加语义**：先按 `dayKey.startsWith(year)`，再叠加自定义区间，两者是**交集**。

> **Android 的一处修正**：iOS 上年份芯片的选中态要求 `timeKind == .all`，导致"先选年份、再选自定义区间"后
> 年份芯片看起来没选中，但两层过滤仍然生效。Android：**两层各自显示自己的选中态**，并在摘要行同时显示两枚 chip。

### 2.3 统计卡（5 格等宽）

| 位置 | 标签 | 口径 |
| --- | --- | --- |
| 1 | 省市 | 去重 `country + region1` 集合大小 |
| 2 | 城市 | 去重 `country + region1 + region2` |
| 3 | 国家 | 去重 `country` |
| 4 | 片段 | 已定位片段计数 |
| 5 | 天数 | 去重 `day_key` |

数值 20sp semibold `onSurface`，标签 12sp `onSurfaceVariant`；两行都 `maxLines = 1` + 缩放，不换行。

### 2.4 年度趋势图（自绘）

| 项 | 值 |
| --- | --- |
| 图类型 | 柱状图；x = 年份（**升序**分类轴）、y = 该年**去重记录天数** |
| 柱 | `primary` 实心，柱顶圆角 4dp，最小高 3dp（值为 0 时画一条底边） |
| 网格 | 水平线，`outlineVariant @70%`，5 档 |
| 轴 | 只定制 y 轴（左侧，带数值标签）；x 轴标签在柱下方 |
| 高度 | 竖屏 **168dp**（含轴标签区）；平板横屏 **200dp** |
| 字号 | 轴标签 12sp，随动态字体缩放 |
| 交互 | **无**（iOS 也没有）。**不要**加点击筛选 —— 会让"点柱子"和"点年份芯片"两个语义打架 |
| 显示条件 | **只有 ≥ 2 个年份时才出现**（iOS 同）。所以它没有空态 |

### 2.5 地点清单（三级树）

- 层级：**国家 → 省/州 → 城市**。
- 计数**含子孙**：国家的数字 = 它下面所有片段数（不是子节点个数）。
- 同级按**计数降序**。
- 每级缩进 **16dp**；非叶子节点才有可旋转的 `chevron_right`（展开时转 90°，250ms）。
- 行高 46dp（一级）/ 40dp（二级及以下）。
- 展开状态**跨筛选保留**（切年份不清空展开）。

### 2.6 空态

- 没有任何地点记录 → 清单卡换成空态：`place` 图标 40dp + 「还没有地点记录」。
- 统计卡照常显示 0；趋势卡不显示。

### 2.7 平板横屏

统计整行在上；下方并排：**趋势图（flex 撑满）| 地点清单（固定 300dp，内部滚动）**。
清单在窄栏里默认只展开到国家一级。

## 三、设置

### 3.1 结构

五张卡，顺序固定：**通用 → 日记规则 → 提醒 → 数据 → 关于**。

- 卡片 = 16dp 圆角 `surfaceContainerLow`；行高 **64dp**（带副标题）/ 56dp（不带）；图标徽标 **40dp** 圆、`secondaryContainer` 底。
- 分隔线 `outlineVariant`，左缩进 **72dp**（= 16 + 40 + 16，与**文字**左对齐，不对齐图标）。
- 列数：`< 700dp` 1 列 / `700–999dp` 2 列 / `≥ 1000dp` 3 列。

### 3.2 三种行的可点范围（都必须整行可点）

| 类型 | 结构 | 点击 |
| --- | --- | --- |
| **取值行** | 徽标 + 标题 + 副标题 + 取值 + `chevron_right` | 整行 → 打开 ModalBottomSheet 或系统设置 |
| **菜单行** | 同上 | 整行 → 打开 `DropdownMenu`（锚在行尾） |
| **开关行** | 徽标 + 标题 + 副标题 + `Switch` | **整行** → 切换开关（不必精确点中开关本体） |

> v2 的 `Switch` 行曾经只有开关本体可点 —— 这是硬性体验问题，已改。

### 3.3 通用卡

| 行 | 图标 | 标题 / 副标题 | 控件 | 取值 |
| --- | --- | --- | --- | --- |
| 语言 | `language` | 语言 / 应用内显示语言 | 菜单 | 跟随系统 / **中文** / **English**（后两项是字面量，不随语言变化） |
| 主题 | `dark_mode` | 主题 / 浅色、深色或跟随系统 | 菜单 | 跟随系统 / 浅色 / 深色 |

- 切语言：写设置 → 重新加载字符串 → **不重建整棵树**（用 `CompositionLocal` 下发语言）。
  iOS 用 `.id()` 重建整棵树，会丢失搜索条件、足迹展开态、滚动位置 —— **不要照抄**。
- 切主题：写设置 → 重组 `JustDiaryTheme`（`CompositionLocal`）。

### 3.4 日记规则卡

| 行 | 图标 | 标题 / 副标题 | 控件 | 取值 / 行为 |
| --- | --- | --- | --- | --- |
| 新一天的开始时间 | `schedule` | 新一天的开始时间 / 这个时间前算前一天 | 取值 → 小时滚轮面板 | 「凌晨 4:00」这类语义文案（见 §3.7） |
| 一周从哪一天开始 | `calendar_month` | 一周从哪一天开始 / 日历以周几开头 | 菜单 | 周一 / 周日 |
| 自动记录时间 | `schedule` | 自动记录时间 / **只影响是否显示** | 开关 | 默认开。**纯显示开关**，`start_time_utc` 照常写 |
| 自动插入地点 | `place` | 自动插入地点 / 需要位置信息权限 | 开关 | 默认开。打开时 → 请求权限 + 回填历史 block 的国家/省市 |
| 位置权限 | `my_location` | 位置权限 / 地点只存在本机 | 取值 → 系统设置 | **条件行**：仅当「自动插入地点」打开时出现。取值：精确 / 模糊 / 未授权 |
| 允许修改 / 删除历史日记 | `edit` | 允许修改 / 删除历史日记 / 历史日期只能改，不能新增 | 开关 | 默认**关** |

**改「新一天的开始时间」的流程（Android 修正版）**：

```
选好小时 → 先试算会改变归属日的日记篇数（previewDayKeyChanges，只算不写）
  ├─ 0 篇 → 直接保存 + 重算
  └─ N 篇 → 先弹确认：「有 N 篇日记会因为规则变化改变归属日，是否继续？」
                 （取消 / 继续）→ 继续才保存 + 重算
```

iOS 是先改后提示（且只在有冲突时告知），Android **先问再改**。
预览与执行共用同一个纯函数 `planDayKeys`，所以"预览说 0 篇、执行却动了 3 篇"不可能发生
（`DayKeyPlanTest` 6 条断言守住）。

> **顺带修掉一个两端共有的数据损坏缺陷。** `recomputeDayKeys` 的冲突判定写的是
> "谁的新键等于我的**旧**键"，而这个条件按定义恒为真/恒为假 —— 冲突分支从未进入，
> `conflicts` 永远是 0。真撞上时（目标键被一个不移动的记录占着）第二阶段的 `UPDATE`
> 会违反 `day_key UNIQUE`：iOS 被外层 `try?` 吞掉并当成"0 冲突"，但**临时键已经写进去**，
> 归属日残留成 `tmp#N`。Android 按真实约束判断（目标键被不移动的记录占着 → 记冲突并跳过），
> `day_key` 在"不撞车"的所有情形下与 iOS 完全一致。

### 3.5 提醒卡

| 行 | 图标 | 标题 / 副标题 | 控件 | 取值 / 行为 |
| --- | --- | --- | --- | --- |
| 写日记提醒 | `notifications` | 写日记提醒 / 当天未写日记时提醒我 | 开关 | 默认开。开 → 请求通知权限 → 排期；关 → 取消全部 |
| 提醒时间 | `schedule` | 提醒时间 / 每天提醒一次 | 取值 → 时间滚轮面板 | 默认「晚上 9:00」，跟随系统 12/24 小时制 |
| 通知权限 | `notifications` | 通知权限 / 关闭后无法收到提醒 | 取值 → 请求权限 | **条件行**：仅当提醒开着**且**权限未授予时出现。**用枚举判状态，不用文案比较** |

- 提醒实现：`WorkManager` 每日任务（**不用精确闹钟权限**）。
- 时间选择器用系统 `TimePicker`（跟随语言与 12/24 小时制），**不要手搓双滚轮**。

### 3.6 数据卡与关于卡

| 行 | 图标 | 标题 / 副标题 | 控件 | 行为 |
| --- | --- | --- | --- | --- |
| 导出全部日记 | `upload` | 导出全部日记 / 生成 .jdiary 备份包 | 菜单（无取值） | 两项：**仅日记数据** / **日记 + 设置** → 忙碌遮罩 → 系统分享（`ACTION_SEND`） |
| 导入备份 | `download` | 导入备份 / 从其他设备恢复日记 | 取值 | SAF 选文件 → 「导入方式」对话框 → 忙碌遮罩 → 结果对话框 |
| 版本 | `info` | 版本 / `1.0（36）` | **不可点**（无 `chevron_right`） | iOS 这一行画了箭头但点了没反应 —— 不要照抄 |

**导入方式对话框**：

| 项 | 内容 |
| --- | --- |
| 标题 | 导入方式 |
| 正文 | 备份里有 N 天日记与目标设备重复。 |
| 左键 | 取消 |
| 中键 | 跳过已有日记 |
| 右键 | **覆盖已有日记**（`error` 色 —— iOS 两个按钮同色，这是缺陷） |

**结果对话框**：标题「导入完成」/「导入失败」；正文给出新增 / 跳过 / 覆盖的天数、片段数、图片数；
带了设置时追加「已同时恢复应用设置。」；**单键「好」**。

> 设置页**没有**「清空全部日记 / 重置」入口（见 `README.md` Q1）。唯一的破坏性路径是导入时选「覆盖已有日记」。

### 3.7 时刻的语义文案

```
0        → 凌晨 0:00
1 – 5    → 凌晨 N:00
6 – 11   → 上午 N:00
12       → 中午 12:00
13 – 17  → 下午 N:00
其它      → 晚上 N:00        // 但 21:00 → 「晚上 9:00」
```

**跟随系统的 12/24 小时制与 App 语言**，不写死。

### 3.8 忙碌遮罩

导出 / 导入期间：全屏 `scrim`（`onSurface @32%`）+ 居中圆角卡片（28dp 圆角，44dp 不确定进度圈，13sp 文案）。
**不可取消**（导入中途取消会留下半写状态）。文案按动作区分：「正在生成备份…」/「正在导入备份…」。

## 四、通用规则（三屏共享）

| 规则 | 说明 |
| --- | --- |
| 页头 | 大标题 28sp，`padding: 16dp`，**不用 `LargeTopAppBar`**（滚动时不收起，保证定位感） |
| 页边距 | 恒 16dp，**不含安全区** |
| 卡片 | `surfaceContainerLow`，16dp 圆角，无阴影，卡间距 12dp |
| 空态 | 统一形态：图标 40dp（`onSurfaceVariant @55%`）+ 主文案 16–18sp + 副文案 14sp `onSurfaceVariant` + **可选的一个出路按钮** |
| 加载态 | 首屏用骨架行（`surfaceContainerHigh` 圆角条）；翻页用底部小进度圈；**不要用整屏菊花** |
| 长列表 | 统一底部留白 24dp + `navigationBarsPadding()` |
| 下拉刷新 | **不做**（数据是本地的，且变更由 `diaryVersion` 事件驱动） |

## 五、验收清单
